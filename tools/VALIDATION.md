# What the checks establish

These checks validate the structure and reproducibility conventions of the
record. They do not verify the mathematics in a LaTeX proof. A green build is
not evidence of independent review, proof completeness, or formal coverage.

## Commands

| Command | Scope |
| --- | --- |
| `make check-source` | Literal references, ownership, all three manifests, glossary rows and terminology; no PDF build required. |
| `make test` | Adversarial tool tests in temporary fixtures; no worked-example mathematics, TeX or Lean required. |
| `make all` | All six PDFs, source/log checks and the tool regression suite. |
| `make smoke` (or `make audit`) | The project's fast computational subset only; not reproduction of all claims. |
| `make formal` | The opt-in Lean build; axiom review and specification correspondence still require separate checks. |

The legacy `perl tools/check_manuscript.pl` entry point delegates to the same
Python checker. Python 3.10 or later, Perl (for the legacy wrapper), Bash, Git and
Make are sufficient for the source checks and tests. The normal manuscript
build additionally needs the existing TeX dependencies.

The tests and lexer are independent of the worked example. Initialization
rewrites their project-prefix placeholders just as it rewrites the manuscript.
Do not remove them when starting a new project. In an uninitialised template,
the end-to-end initializer test runs the real initializer in a temporary copy,
then checks the resulting sources, linked generation and audit command. That
one-time test skips after project naming, or in a partial source fixture without
the initializer; the remaining tooling regression tests continue to run.

## Supported source syntax

The checker is deliberately a small lexer, not a partial TeX interpreter.
Comments, escaped percent signs, balanced brace arguments, `\verb`/`\verb*`,
common literal environments, URLs and `\detokenize` are handled explicitly.
Literal `\label`, `\ref`, `\eqref`, `\pageref`, `\autoref`, `\nameref`,
`\dfn`, `\dfnas`, `\term`, `\termas`, `\gkey` and `\gkeyx` arguments are
checked. Identifiers must be literal and contain no whitespace. Do not hide
labels or references in macro definitions or construct them by expansion.

Supported conditionals in checked source are `\iftrue`, `\iffalse` and
`\ifdefined\SCAFFOLDResultsView`, with nested `\else` and `\fi`. Visibility
is evaluated for the entire block, not just its first glossary row. Other
conditionals produce an explicit error rather than an assumed visibility.

Manifests use direct `\input{tex/<owner>/<module>}` commands (an explicit
`.tex` suffix is accepted), `\part` headings and `\appendix`, `\clearpage`
or `\newpage`. Macro-generated paths, manifest indirection and other manifest
commands are rejected. Every results module occurs exactly once in the results
manifest, every route module once in the routes manifest, and every content
module once in the full (`archive.tex`) manifest. Wrong-owner inputs fail.

Preamble macro expansion, catcode changes, arbitrary TeX programming, and
references generated by custom macros are outside the source check's scope.
Keep manuscript structure literal, add explicit lexer support plus adversarial
tests before extending the supported syntax, and still run the complete TeX
build. The log check requires all six expected logs to exist and be readable.

## Dense linking is conservative

Math delimiters and common math environments, comments, literal content,
command tokens, and all balanced mandatory/optional macro arguments are left
unchanged. That includes nested formatting, existing links, URLs and unknown
macros. Consequently some safe prose inside macros is intentionally not linked.
Only plain eligible prose is enriched; original whitespace is retained.
Unsupported or incomplete protected syntax fails instead of producing a
possibly damaged linked tree. A match intersecting a protected region is
rejected even when the whole match is not contained in that region.

Generation checks resolved paths before writing. Output may not overlap the
source tree, contain a symlink in its path, or overwrite an unmarked custom
`tex/` directory. The default legacy `build/linked-src/tex` is supported for
migration. Source symlinks are rejected. Generation is staged before replacing
old output, and a failed final rename restores the previous generated tree.
This protects against accidental paths and ordinary failures, not concurrent
hostile filesystem mutation; do not run concurrent generators into one output.

## Push and CI guarantees

The pre-push hook reads the actual pushed object IDs, peels annotated tags,
and checks each distinct commit once in a clean detached worktree. A dirty
working-tree fix cannot make a broken commit pass, and pushing a non-current
branch checks that branch. Deletions need no build; non-commit targets are
refused explicitly. Temporary worktrees are removed on success and failure.

These are clean builds, not warm working-tree builds, so they can cost more.
The hook intentionally runs `make all`, not every expensive computation or
an opt-in Lean build. It can also be bypassed; receiving-side checks and branch
protection are the enforcement mechanisms, not a local hook.

CI now runs `make check-source test` on both public and private repositories.
This allocates a runner even on private repositories. The existing private
repository opt-in gates apply to manuscript, computation and Lean jobs only.
The workflow uses read-only repository permissions. Lean remains opt-in.

## Evidence and formal-review boundaries

Keep author-asserted complete proofs, independently reviewed proofs, finite
computational verification and kernel-checked formal statements distinct.
Before promotion, a reviewer should check quantifiers, hypotheses, dependencies,
finite ranges and the precise correspondence to any formal statement.

For future computational records, retain a claim identifier, tested domain,
exact command and seed, source revision or hash, environment, exit status and
output hash. Do not retrospectively invent provenance for old logs. A rerun of
the same implementation is reproduction, not an independent verification of
its algorithm. The current smoke target does not enforce a complete claim
registry or detect every stale log; adding such a registry is separate work.

Likewise, a successful `lake build` does not by itself enforce a no-`sorry`
or approved-axioms policy. Inspect axiom dependencies, and review changes to
central definitions: tests using the same evolving predicate can pass while
its intended meaning changes. Automated axiom allowlisting and independent
specification-equivalence checks are not implemented by this tooling patch.
